# QuickBite — Food Delivery Application & DevOps CI/CD Pipeline

Welcome to the **QuickBite** project repository. This project covers both **Assignment 1 (Agile Requirements & Sprint Planning)** and **Assignment 2 (DevOps CI/CD Pipeline)** based on the DevOps Lab Record curriculum.

---

## 🔍 Root Cause Diagnosis & Resolution

### Problem Statement
When opening the application in the browser at `http://localhost:3000/`, it previously rendered only one line of plaintext: `"Welcome to QuickBite!"` (or `"QuickBite"`).

### Root Cause
1. **Placeholder Root Route:** The initial `app.js` file contained only a minimal stub `app.get('/', (req, res) => res.send('Welcome to QuickBite!'))` originally scaffolded just to pass a simple `/health` CI/CD test.
2. **Missing Frontend Assets:** There were no static frontend HTML, CSS, client-side JavaScript controllers, or multimedia assets served.
3. **Missing Business Logic & API Layer:** There were no backend REST API endpoints for restaurant cataloging, food search, single-restaurant cart rules, simulated checkout, order lifecycle tracking, ratings, or kitchen dispatch.

### Resolution Implemented
1. **Complete Modern Frontend (`public/`):**
   - **`index.html`:** Semantic HTML5 interface containing the brand header, delivery location selector, instant search, promotional coupon carousel (`WELCOME50`, `QUICKBITE20`, `TASTY10`), restaurant cards, dish cards, cart slide-over drawer, simulated payment modal, live order tracking stepper, post-delivery reviews modal, and kitchen partner dashboard.
   - **`css/styles.css`:** Responsive, modern CSS with smooth animations, mobile/desktop media queries, veg/non-veg badge pills, and accessible UI components.
   - **`js/app.js`:** Client-side application controller managing cart state, single-restaurant cart collision detection, live debounced search, Web Audio API sound alerts, and real-time order tracking.
2. **Modular Express REST API Backend (`src/`):**
   - **`src/data.js`:** Pre-populated dataset of restaurants (including open restaurants and clearly flagged closed restaurants), multi-cuisine dishes, promo codes, and demo user accounts.
   - **`src/store.js` & `src/routes.js`:** In-memory store supporting all 10 Agile User Stories with testable boundary checks and acceptance criteria.
3. **Comprehensive Native Automated Test Suite (`test.js`):**
   - 13 automated integration tests running via Node.js native test runner (`node --test`), verifying `/health`, `/`, and all 10 user stories.

## 🚀 Local Setup & Running (Windows PowerShell)

### Prerequisites
- **Node.js** (v18 or higher recommended; verified with Node.js v24)
- **npm** (v9 or higher)

### 1. Install Dependencies
```powershell
npm install
```

### 2. Start the QuickBite Application Server
```powershell
npm start
```
Console output:
```text
QuickBite running on port 3000
Access the website at: http://localhost:3000
```

### 3. Open in Browser
Open your browser and navigate to:
```text
http://localhost:3000
```
You will be greeted by the full, interactive **QuickBite Food Delivery Application**, featuring:
- Live restaurant browsing with veg/non-veg tags
- Dynamic multi-filter toolbar (search, cuisine chips, rating, budget, veg-only)
- Interactive cart drawer with coupon discount calculator
- Simulated checkout with UPI, Card, and Cash on Delivery
- Live milestone delivery tracker with audio alerts and simulation controls
- Restaurant kitchen partner dashboard
- Order history with 1-click reorder
- Verified post-delivery star rating form
- Interactive Agile Jira Stories status drawer

## 🚫 Preserved Docker-Free CI/CD Pipeline

The GitHub Actions CI/CD pipeline configured in `.github/workflows/ci-cd.yml` remains completely **Docker-free**:
- **Continuous Integration (`build-and-test`):** Checks out code, sets up Node.js 20, installs dependencies via `npm install`, and runs all automated tests via `npm test`.
- **Continuous Delivery (`deploy`):** Automated simulated deployment triggered on push to `main` upon successful completion of test stages (`needs: build-and-test`).
- **Zero Third-Party Dependencies:** Eliminates Docker daemon requirements, registry logins, and external tokens.
