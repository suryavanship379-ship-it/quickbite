## 📋 Assignment Overview

### Assignment 1: Agile Requirements and Sprint Planning
- **Full Documentation:** [`docs/assignment-1-agile.md`](docs/assignment-1-agile.md)
- **Domain:** Food Delivery System (QuickBite)
- **Epics:** Account Management, Restaurant Discovery, Ordering & Payment, Order Fulfilment, Feedback & Retention
- **User Stories:** 10 detailed user stories with testable acceptance criteria
- **Estimation:** 42 Story Points total using the Fibonacci scale ($1, 2, 3, 5, 8, 13$), benchmarked against baseline story `US7` (2 points)
- **Sprint Planning:** 3 two-week sprints (Team velocity $\approx 14$ points/sprint)
- **Release Planning:** Release 1 / MVP at End of Sprint 2 (US1–US5, US8, US9) and Release 2 at End of Sprint 3 (US6, US7, US10)
- **Prioritization:** MoSCoW framework (Must: 27 pts, Should: 10 pts, Could: 5 pts)
- **Viva Questions:** 5 comprehensive Q&As covering User Stories, Acceptance Criteria, Story Points, Velocity, and Sprint vs. Release planning

### Assignment 2: DevOps CI/CD Pipeline
- **Full Documentation:** [`docs/assignment-2-cicd.md`](docs/assignment-2-cicd.md)
- **Stack:** Node.js 20, Express, Native Node Test Runner (`node:test`), GitHub Actions
- **Pipeline Workflow:** Two-stage automated pipeline configured in `.github/workflows/ci-cd.yml`:
  1. `build-and-test`: Checks out repository code via `actions/checkout@v4`, sets up Node.js 20 via `actions/setup-node@v4`, installs dependencies via `npm install`, and executes automated tests via `npm test`.
  2. `deploy`: Automated simulated deployment job that executes only on pushes to `main` after `build-and-test` succeeds (`needs: build-and-test`), outputting simulated deployment confirmation (`"QuickBite deployment successful (simulated)."`).
- **Docker-Free Execution:** Completely eliminates Docker dependencies, container build/push steps, and Docker Hub credentials from the pipeline.
- **Viva Questions:** 5 Q&As on CI/CD principles, GitHub Actions components, simulated deployment verification, and workflow job sequencing (`needs`).

## 🚀 Local Setup & Running (Windows PowerShell)

### Prerequisites
- **Node.js** (v18 or higher recommended; verified with Node.js v24)
- **npm** (v9 or higher)

### 1. Install Dependencies
In your PowerShell terminal, navigate to the project directory and run:
```powershell
npm install
```

### 2. Run the Application
Start the QuickBite server locally:
```powershell
npm start
```
The console will log:
```text
QuickBite running on port 3000
```

### 3. Verify the Endpoints in Your Browser or Terminal
Open a browser or run PowerShell requests:
- **Welcome Route:** `http://localhost:3000/`  
  *Response:* `Welcome to QuickBite!`
- **Healthcheck Route:** `http://localhost:3000/health`  
  *Response:* `{"status":"ok"}`

PowerShell test commands:
```powershell
Invoke-RestMethod -Uri "http://localhost:3000/"
Invoke-RestMethod -Uri "http://localhost:3000/health"
```

## 🚫 Docker-Free Architecture

This project and its CI/CD pipeline are completely **Docker-free**:
- **No Docker Required:** Docker Desktop, Docker Daemon, and container tools are entirely excluded. The application runs and is tested directly on Node.js 20.
- **No Container Builds or Registry:** Docker image builds, Docker Hub logins, and image publishing have been completely removed from the workflow.
- **Pure Native Automation:** Continuous Integration (`build-and-test`) and Continuous Delivery (`deploy`) run natively via GitHub Actions.

## ☁️ GitHub Setup & CI/CD Pipeline Execution

The CI/CD pipeline is fully automated through **GitHub Actions** and requires **no external services, third-party accounts, or Docker Hub credentials**.

### Step 1: Initialize Git and Commit Code (Local Windows Terminal)
```powershell
git init
git branch -M main
git add .
git commit -m "feat: configure Docker-free GitHub Actions CI/CD pipeline"
```

### Step 2: Create a Repository on GitHub
1. Open your browser and go to [GitHub](https://github.com).
2. Click **New Repository**.
3. Name the repository `quickbite` (or your preferred name), set it to **Public** or **Private**, and leave "Initialize with README" unchecked.
4. Click **Create repository**.

### Step 3: Push Local Code to GitHub
Link your remote repository and push to the `main` branch:
```powershell
git remote add origin https://github.com/suryavanship379-ship-it/quickbite.git
git push -u origin main
```

### Step 4: Verify the Workflow Run in GitHub Actions
1. In your GitHub repository, navigate to the **Actions** tab.
2. Select the latest workflow run: **CI/CD Pipeline**.
3. Verify the execution of the pipeline jobs:
   - **`build-and-test`**: Automatically runs on every push and pull request to `main`. It checks out the repository (`actions/checkout@v4`), sets up Node.js 20 (`actions/setup-node@v4`), installs dependencies (`npm install`), and executes automated tests (`npm test`).
   - **`deploy`**: Runs automatically after `build-and-test` finishes successfully (only on pushes to `main`). It executes the simulated deployment and logs:
     ```text
     Deploying QuickBite to staging server...
     Application: QuickBite Food Delivery Service
     Status: Build & Tests Passed Successfully
     Simulation: Server deployment completed successfully.
     QuickBite deployment successful (simulated).
     ```
4. Both jobs will complete with green checkmarks (passed), achieving automated continuous integration and delivery without Docker.
