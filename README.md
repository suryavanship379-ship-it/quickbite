## 📋 Assignment Overview

### Assignment 1: Agile Requirements and Sprint Planning
- **Full Documentation:** [`docs/assignment-1-agile.md`](docs/assignment-1-agile.md)
- **Domain:** Food Delivery System (QuickBite)
- **Epics:** Account Management, Restaurant Discovery, Ordering & Payment, Order Fulfilment, Feedback & Retention
- **User Stories:** 10 detailed user stories with testable acceptance criteria
- **Estimation:** 42 Story Points total using the Fibonacci scale ($1, 2, 3, 5, 8, 13$), benchmarked against baseline story `US7` (2 points)
- **Sprint Planning:** 3 two-week sprints (Team velocity $\approx 14$ points/sprint)
- **Release Planning:** Release 1 / MVP at End of Sprint 2 (US1–US5, US8, US9) and Release 2 at End of Sprint 3 (US6, US7, US10)
- **Prioritization:** MoSCoW framework (Must: 27 pts, Should: 10 pts, Could: 5 pts)
- **Viva Questions:** 5 comprehensive Q&As covering User Stories, Acceptance Criteria, Story Points, Velocity, and Sprint vs. Release planning

### Assignment 2: DevOps CI/CD Pipeline
- **Full Documentation:** [`docs/assignment-2-cicd.md`](docs/assignment-2-cicd.md)
- **Stack:** Node.js, Express, Native Node Test Runner (`node:test`), Docker (`node:20-alpine`), GitHub Actions
- **Pipeline Workflow:** Three sequential stages configured in `.github/workflows/ci-cd.yml`:
  1. `build-and-test`: Checks out code, configures Node.js 20, installs dependencies, and runs automated tests.
  2. `docker-build-push`: Authenticates to Docker Hub using encrypted secrets (`DOCKER_USERNAME`, `DOCKER_PASSWORD`), builds the Docker image, and pushes `<username>/quickbite:latest`.
  3. `deploy`: Simulated staging deployment step following successful container push.
- **Viva Questions:** 5 Q&As on CI/CD principles, GitHub Actions components, secrets management, and workflow job sequencing (`needs`).

## 🚀 Local Setup & Running (Windows PowerShell)

### Prerequisites
- **Node.js** (v18 or higher recommended; verified with Node.js v24)
- **npm** (v9 or higher)

### 1. Install Dependencies
In your PowerShell terminal, navigate to the project directory and run:
```powershell
npm install
```

### 2. Run the Application
Start the QuickBite server locally:
```powershell
npm start
```
The console will log:
```text
QuickBite running on port 3000
```

### 3. Verify the Endpoints in Your Browser or Terminal
Open a browser or run PowerShell requests:
- **Welcome Route:** `http://localhost:3000/`  
  *Response:* `Welcome to QuickBite!`
- **Healthcheck Route:** `http://localhost:3000/health`  
  *Response:* `{"status":"ok"}`

PowerShell test commands:
```powershell
Invoke-RestMethod -Uri "http://localhost:3000/"
Invoke-RestMethod -Uri "http://localhost:3000/health"
```

## 🐳 Docker Build & Execution (Local)

When Docker Desktop is running on your Windows machine, you can build and run the container locally:

### 1. Build the Docker Image
```powershell
docker build -t quickbite:latest .
```

### 2. Run the Container
```powershell
docker run -d -p 3000:3000 --name quickbite-app quickbite:latest
```

### 3. Verify Container is Running
```powershell
docker ps
Invoke-RestMethod -Uri "http://localhost:3000/health"
```

### 4. Stop and Clean Up Container
```powershell
docker stop quickbite-app
docker rm quickbite-app
```

## ☁️ GitHub & Docker Hub Setup (For Live Pipeline Execution)

To run the GitHub Actions pipeline in the cloud:

### Step 1: Initialize Git and Commit Code (Local Windows Terminal)
```powershell
git init
git branch -M main
git add .
git commit -m "feat: complete QuickBite Agile documentation and CI/CD pipeline"
```

### Step 2: Create a Repository on GitHub
1. Open your browser and go to [GitHub](https://github.com).
2. Click **New Repository**.
3. Name the repository `quickbite` (or your preferred name), set it to **Public** or **Private**, and leave "Initialize with README" unchecked.
4. Click **Create repository**.

### Step 3: Push Local Code to GitHub
Link your remote repository and push:
```powershell
git remote add origin https://github.com/<YOUR_GITHUB_USERNAME>/quickbite.git
git push -u origin main
```

### Step 4: Configure Docker Hub Secrets on GitHub
1. Log in to [Docker Hub](https://hub.docker.com/).
2. Click your avatar in the upper right $\rightarrow$ **Account Settings** $\rightarrow$ **Security** $\rightarrow$ **New Access Token**.
3. Create a token named `github-actions-quickbite` with **Read, Write, Delete** permissions and copy the token secret.
4. Go to your GitHub repository $\rightarrow$ **Settings** $\rightarrow$ **Secrets and variables** $\rightarrow$ **Actions**.
5. Click **New repository secret** and add:
   - **Secret 1:**
     - Name: `DOCKER_USERNAME`
     - Value: *(Your Docker Hub username, e.g. `priya123`)*
   - **Secret 2:**
     - Name: `DOCKER_PASSWORD`
     - Value: *(Your Docker Hub Access Token or Account Password)*

### Step 5: Verify the Workflow Run in GitHub Actions
1. In your GitHub repository, click on the **Actions** tab.
2. Select the latest workflow run: **CI/CD Pipeline**.
3. Watch the three stages execute sequentially:
   - `build-and-test` (passes tests)
   - `docker-build-push` (builds and pushes image to Docker Hub)
   - `deploy` (simulates staging deployment)
4. Visit your Docker Hub profile to view the published `<username>/quickbite:latest` container image.
